# Rust 云端霸权规则核与房间服务

这是原 Go 工程旁的模块化单体：纯规则解释器、角色隐私投影和 SQLite 房间服务。v2.1只开放已逐卡实现的25张真实玩家牌及4种实际卡图核对过的地区：DQJC107、DQJC112各3张，DQJC113、DQJC114各2张，共10张。世界牌配置同样为受限卡池的自组配置，不是官方套牌。五套50张牌组是受限卡池的自组预组，不是官方预组；原四套保持不变，新增“牺牲与响应”包含末日信徒、深渊细语、谋杀和阿塔玛斯奉献仪式。

原稿依据和卡图哈希见 [data/source-verification.json](data/source-verification.json)；接口和原 PDF 印刷页码见 [云端切片契约](../docs/HEGEMONY_CLOUD_SLICE_2026-10-02.md)。

## 启动与验证

```sh
cargo run -p hegemony-server
cargo test -p hegemony-server
```

实际房间的离线审计使用只读 SQLite 快照，输出匹配结果、版本与 SHA-256 摘要，不输出牌面、seed 或令牌：

```sh
cargo run -p hegemony-server --bin hegemony-audit -- rust-game-v2.1.sqlite3 ROOM_ID
```

可在房间 ID 后追加多个房间。全部精确匹配时退出 0；发现不一致时退出 1。审计不修改数据库，也可在服务运行时进行。

默认监听8090，SQLite为当前目录的rust-game-v2.1.sqlite3，可通过PORT、HEGEMONY_DB设置。WEB_DIST默认web/dist；构建过的客户端由同一服务托管。开发客户端通过Vite的/api代理访问服务。

状态格式为2，规则版本hegemony-pdf-v1、卡池limited-v2.1、引擎rust-v0.2.1。旧v1及rust-v0.2.0/limited-v2房间必须使用原版本binary和原数据库；v2.1启动、审计和WASM导入先验证版本，明确拒绝不匹配状态，不提供静默迁移。既有8090/8091旧进程及数据库未由本次改造重启或修改。

Rust 1.90.0。本工作区的工具链在 /workspace/.cloud-setup/cargo/bin；如未在 PATH 中，可使用：

```sh
export PATH=/workspace/.cloud-setup/cargo/bin:$PATH
export RUSTUP_HOME=/workspace/.cloud-setup/rustup
export CARGO_HOME=/workspace/.cloud-setup/cargo
```

## 状态与时序

每局使用一个串行锁。已验证动作在状态副本上执行；拒绝动作不会修改状态、版本、身份序列或 PRNG。SQLite FULL 同步事务同时写入完整状态、版本化回放日志和 commandId 原始响应；提交成功后才更换内存状态、广播 SSE 和返回确认。

随机座位令牌只保存 SHA-256 摘要，HTTP 状态、动作和 SSE 都必须携带所属房间的 Bearer 令牌。邀请只能占大厅空座。SSE 始终返回请求者自己的 View；其他玩家只有手牌数量，队友暗藏者也不公开牌面。公开 waitingChoice 只含选择者、类型和标题，完整 pendingChoice 只给选择者。

固定版本、初始 seed 和 journal 可通过 Store::replay 完整重演。重开延续确定性 PRNG 序列，产生新的洗牌。SQLite 重启恢复包含堆叠、效果续体、当前快速窗口、团队让过记录和待选。离场、进入新区域类型与翻面使用新 instanceId；普通机动在场移动保留实体身份和横置状态。

外科医生保持公开：不能秘密派遣，治疗行动支付2资产并横置本卡。真进场/现身产生进场及进入地区事件；普通场内移动只产生进入地区事件，不重复进场能力或独有检查，同地区移动无变化。

资产付款自动使用本人的未横置资产，忠诚同时计算资产派系及魔法领域。建立资产和秘密派遣不入栈。现身支付完整印刷费用并保留横置状态；事务和角色能力进入可响应的后入先出堆叠。每个准备、抓牌、行动、对抗前后、赢区前和结束步骤都有快速行动窗口。

## 有限通用规则

[rules.rs](src/rules.rs)将真实牌绑定到类型化AbilitySpec、费用、目标槽、操作序列、触发、数值trait和修饰声明；[resolution.rs](src/resolution.rs)解释这些有限原语。生产解释器不比较具体牌号或牌名，不解析卡牌自然语言，也不执行任意脚本。BoardSelector只处理群体非目标查询；它不应用屏障、护盾或指定目标的合法性。DamageMatching先同时赋予全部伤害，再批量死亡并统一排列触发。

每个入栈对象保存固定actor、来源最后已知信息、声明时绑定的旧实例及目标谓词、公开目标快照、已支付费用、一次性guard状态和效果游标。整个对象在开始结算时重校验目标；单目标失效取消全部效果、费用不退，事务仍入墓。已通过guard的操作中途选择恢复不重新检查整个对象、不重新支付。SourceRef失踪只令针对来源自身的操作无效果，余下合法效果继续。

费用牺牲与效果牺牲区分时机，且牺牲、消灭、致死保留不同原因；角色均能产生死亡触发。额外牺牲费用选当前由付款者控制的角色，牌最终进入拥有者墓地。费用整体原子支付并入栈后，在稳定点声明死亡触发，因此可响应的是已发动能力/触发，费用不会被响应。光环离开后导致防御归零会即时死亡（霸权印刷P6）。

末日信徒的减费只作用于本回合下一张正面打出的鸣钟教派或血图标牌：资产费用下限0，忠诚和额外牺牲费用照常；现身不减费、不消耗该修饰。深渊细语从牌库底置手不是抓牌，牌库只有0/1张时取得现有数量，不因此退出游戏。多目标集合可由内部目标槽表达，但部分目标失效规则尚缺原稿证据；JC021/JC062不在开放卡池。注册时检查每项能力与模式至多一个目标槽、min=max=1并拒绝嵌套玩家遍历，错误包含牌号与能力/模式键。

Action新增abilityId、costSelected。CardView为本人手牌给effectiveCost；StackView给脱敏targetSummaries和resolutionState，明确原目标仍合法、已离场、条件改变或已通过结算检查，不将离场旧目标关联至新实体。合法动作的额外牺牲费用列出角色名、地区和公开实例编号。

## 验证覆盖

历史8a16cf3验收通过38项测试（31规则、7服务）及Native/WASM一致性。v2.1新增声明校验、移动原语事件边界、外科医生横置费用及旧版本拒绝回归；当前测试套件含42项（35规则、7服务），最终固定提交后的全量验收另行记录。

规则测试涵盖25张牌和4种地区的印刷能力、临时图标、差值奖励、护卫和杀伤、屏障与护盾、同地区目标再验证、独有牺牲、墓地与牌库回收、机动顺序与响应、赢区牌底顺序和撤回、团队优先权和距离、弃牌和预测选择、隐藏投影、退出及队友续局，以及完整两人与四人游戏、重开和确定性回放。

新增真实Action序列覆盖谋杀被末日信徒费用牺牲响应、葬礼目标被窃尸人响应回收后连同抓牌失效、潜伏再现身后旧链不能命中新实体、来源离场而LC23余下目标操作继续、两队全体让过及两个队友分别响应、深渊细语0/1张牌库与控制/拥有区别、恶意额外费用导致整个动作回滚、减费忠诚/现身/到期及仪式选择恢复。

服务集成测试涵盖令牌权限、commandId 去重、版本冲突、拒绝无变化、待选持久恢复、SSE 刷新和故障事务回滚。模拟 SQLite 提交路径错误时，服务不确认、不广播、不改变可读状态。

SQLite断点测试额外暂停在费用牺牲触发声明，以及已通过guard的效果选择；重开和重复命令不重复支付、牺牲、触发或效果。最终seed+journal审计精确匹配。Native/WASM使用同一个核；[WASM说明](../rust-game-wasm/README.md)记录实际逐步一致性验证。
