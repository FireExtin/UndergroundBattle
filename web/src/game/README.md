# 可玩云端客户端

默认入口 `/` 是 React 对战大厅与牌桌，`/legacy-debugger` 保留原 Go 调试器。
所有牌桌动作来自服务端 `legalActions`，客户端只选择和提交这些完整动作，不展示任意 JSON 编辑器。
大厅从 `/api/catalog` 展示四套受限真实卡池的 50 张自组预组；不能视为官方预组。

## 运行与验证

Rust 对战服务默认监听 `8090`，并提供构建后的 `web/dist`。
在 `web` 目录运行 `npm run dev` 时，Vite 将 `/api` 代理到 `8090`；独立的 `/api/debugger` 代理到可选的 Go 服务 `8080`。
生产环境中旧调试器界面依旧可打开；连接 Go 实时服务需要同源反向代理该路径，否则原有离线示例仍可使用。

`npm test` 覆盖邀请加入、50 张牌组选择、房间恢复、认证 SSE 分帧、过期版本同步、动作选择、目标与牌库排序、伤害分配、丢失确认的幂等重试。
`npm run build` 完成 TypeScript 检查与生产构建。
真实双浏览器与四浏览器对局由云端验收脚本覆盖。

## 状态与恢复

- `api.ts` 通过 `Authorization: Bearer` 发送本机座位令牌；邀请链接只含房间邀请码。实时流使用认证 `fetch` 读取 SSE，不把令牌放入 URL。
- `useGame.ts` 在本机保存不含牌桌快照的 `hegemony.session.v1`：房间、邀请码、随机令牌与席位。刷新时重新请求本人的投影，再建立 SSE；断线时持续退避重连。
- 服务端视图始终是规则真相源；新视图按房间与单调版本合并。409 显示说明并同步返回的最新视图；已确认拒绝显示错误并再次同步。
- 提交前保存 `hegemony.pending.v1` 中的命令 ID、期望版本及原始动作。网络失败或 5xx 只用同一命令 ID 重试；结果未确认时阻止新动作，并提供“确认上一行动”。刷新也会继续确认该命令，避免丢失响应造成重复行动。
- `pendingChoice` 仅供本人选择；公开的 `waitingChoice` 让全桌单独看见当前选择者，与优先权团队分开。
- “返回大厅”保留本机座位令牌，大厅提供“回到原牌桌”；创建或加入新牌桌会保存新座位。

## 展示与选择

`CardTile` 从目录读取费用、忠诚、永久与白底先手图标、完整文字。地区上的简卡显示服务端即时图标、横置与伤害；点选后显示完整详情与当前合法动作。暗藏者及资产只呈现投影允许的信息。

暗藏者小卡隐藏防御与伤害标记，标示“不受角色伤害”；自己暗藏牌的详情仍可查看原牌资料，供现身参考。选中手中最后一张角色且可以建立资产时，详情显示非阻塞的费用、忠诚与对抗取舍提示，保留完整合法动作。

`ChoicePanel` 根据服务端选择类型显示界面：一般选择使用 `selected`；调查及牌序使用可上下移动的 `top` / `bottom`；赢区回牌使用可调整顺序的 `selected`；伤害分配总数必须等于 `amount`。仅 `allowDecline` 为真时提供空选择跳过；正数伤害分配必须分完，客户端不会因矛盾的跳过元数据显示跳过按钮。

两人模式的三个地区与四人模式的五个地区采用空间牌桌，其他玩家只显示手牌数量、牌库数量、资产与公开牌。双方计分按玩家分数相加，目标为服务端的 `winScore`。本人的手牌仅来自 `view.hand`。

“无可用行动时自动让过”默认关闭，本机偏好保存于 `hegemony.autoPass.v1`。开启后仅在对局进行中、无本人或他人待选、唯一合法动作为让过、连接已确认且无进行中或未确认命令时等待 550 毫秒提交；版本与条件变化取消等待，每个版本只提交一次。它仍经同一命令确认流程，可随时关闭。

主要自动化测试钩子：`data-card-instance`、`data-action-id`、`data-action-kind`、`data-deck-id`、`data-choice-id`、`data-choice-option`。这些标识不包含座位令牌。
