## 初始七项失败及后续定向复验的调用差异

1. 四项 JC015 测试误用了 XQ16：实际旧目录为费用2的人类律师；且四席队伍为 `seat / 2`，席位1与0同队。`valid_binding` 正确拒绝。改用已准入 JC096（费用4、狗/恶魔；旧能力仅主动快速抓牌，没有被假定为空白的死亡/保护能力），敌席为 `actor+2`。费用3边界另用当前转为吸血鬼的 JC059。保留低费用、当前人类、同队、隐藏、任意地区、借用来源、响应失效和换 instance 语义。
2. 隐藏武器夹具中，新 LC30 查询不计隐藏 JC116，但旧 `character_icon_parts -> attachment_host_valid -> host_icons` 仍贡献该武器的印刷附属图标。因此黑底战斗是4（基础1、新计数1、两个旧附属图标2），防御4；旧路径没有被改写。
3. 移入 JC059 所在地区后，友方旧防御光环使 LC30 防御5变6，新查询自身仍为 `(2,2)`。新 LC30 instance 无旧武器，只有基础2加旧光环1。故真实总值与源绑定修正分别断言。
4. 夹具直接 `remove_board` 留下失效宿主 ID，再 `settle_attachments`，走旧“结附条件失效入拥有者墓地”路径，不触发回收。正常宿主离场由 `leave_board -> host_leaves` 回收 BQ022；实际付费金名重复牺牲和四席 JC015 牺牲都证明回到原拥有者手牌并换 instance。
5. 借用 LC30 的旧直接 `return_hand -> leave_board -> fresh` 回拥有者手牌并换 instance，但保留离场控制者。`reset_zone_card` 才重置 controller=owner；正常牺牲及附属回收使用后者。旧直接回手保留控制者是明确记录的既有边界，未算作已修复，也未扩大此次绿色实现去改旧机制。
6. 初始护卫测试把 controller=1 当敌方，实际同队，所以 `Effect::Damage` 没有敌方选项。改为 controller=2 后，护卫2要求先分配2；横置与借用不改变数值。另补真实 `Window::Before(0,1) -> close_window -> reward -> Effect::Damage -> choose`：两张 JC016 战斗4对 LC30战斗3，差1加旧杀伤2产生伤害3；全给另一个角色原子拒绝，护卫2/另一个1通过。
7. 实际 JC005 响应最初被证据工具直接包装为 SessionAction::Game。原生会话正确要求先决定连锁；工具现在记录真实 BeginResponse、SubmitResponse 两个完整 RoomTransition。摧毁初拥后 JC059恢复当前人类，底部驱魔效果失效，来源牺牲费用不退。
