# v027 显式独立玩家会话：待父线程审阅的前端补丁

输入是用户明确批准的同浏览器多标签方案，基线为已发布 `37a09a2cc0088845657eafd7088f54a2bbc19012`。独立分支 `codex/v027-independent-player-sessions-20261003` 与 JC088 候选分开。本补丁没有合并、推送或部署；Site13 公网仍使用原发布源码。

## 行为与隐私

- 默认普通模式继续使用原有五个 localStorage 键，恢复原席及历史席位；邀请码只定位房间，原席凭据继续由服务器验证。
- 大厅的“开始新的独立玩家会话”是唯一生成新本地命名空间的入口。它不创建房间、不加入房间、不复制普通模式的座位。玩家随后自行点击创建或加入。
- 独立命名空间及其中的当前席、历史席、大厅状态、待确认命令、进房重试凭据保存在 sessionStorage。刷新恢复该标签的原席；大厅再次使用相同邀请码恢复该会话已有席位。切回普通模式读取原来的普通席位。
- 明示关闭标签可能失去独立席位的恢复方式；不承诺重新打开已关闭标签可以恢复。同标签刷新与关闭后重开是不同边界。
- 复制标签可能复制初始 sessionStorage，因而沿用原席。没有探测复制后自动换身份或自动占席。需要另一席时必须显式开启新独立会话，然后自行加入。
- 本地命名空间从不进入 URL、HTTP 请求或服务器身份判断。实际请求继续使用原有 Bearer 座位令牌。没有新增认证入口、服务器参数、投影视图或广播凭据。
- 正在提交进房/命令时禁止切换；有未确认命令时，即使已返回大厅，也禁止切换。独立未确认命令刷新后使用原 actor、原 commandId、原 expectedVersion 和原 action 重试。
- 进房收据同时按命名空间隔离内存与持久化状态，异步响应只清理捕获的原命名空间。自动让过偏好也按会话隔离，以免独立玩家继承普通席的自动操作开关。公开牌组草稿仍使用原有共享库。
- 无跨标签 storage 事件恢复逻辑。sessionStorage 不可访问或命名空间损坏时不回退读取普通席位，避免混用私有凭据；开始新会话失败显示提示，既有普通席存储不变。

浏览器边界依据 [MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage)：存储按标签区分，刷新保留，有 opener 时可复制初始内容，关闭结束页面会话。复制标签的具体操作仍需父线程在其真实浏览器验收。

## 验证

新增 `PlayerSessions.test.tsx` 通过正常 React UI 创建/加入后，由模拟服务器返回测试凭据；没有向存储注入玩家身份。七个原始新增用例在发布基线上全部失败（缺少显式入口），实现后全部通过。另有自动让过隔离变异：将该偏好恢复为共享 localStorage，新增断言失败，退出码 1。

最终默认前端回归：19 文件、169 项通过，包含 9 项新增会话回归。新增未确认命令刷新用例也已通过。`npm run build` 的 TypeScript 与 Vite 构建通过。旧 debugger 测试已有重复 React key 警告，未把它计作会话功能失败。

`docs/evidence/v027-player-sessions-2026-10-03/` 保存红/绿日志、偏好隔离变异、构建与服务器/内核逐文件比对。服务器、原七核、Rust 源码、QA 工具全部与基线字节相同。未改变 D1、public、旧房或卡池；没有运行公网自动游戏。

测试模拟页面卸载/重载以及 sessionStorage 清空后的关闭边界；它们不是实际四人 UI 或复制标签验收。父线程仍需亲自在普通浏览器验证多标签加入、刷新及四席操作，并审阅 diff 后决定是否发布。
