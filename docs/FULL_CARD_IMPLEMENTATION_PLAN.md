## 所有者及集成约束

根代理为唯一集成与发布负责人。共享核心`engine/rules/resolution/catalog`与活动`cards.json`在同一批内只有一名写入所有者；UI、隔离测试、原稿证据可按清楚文件边界并行。使用既有目录成果，不再平行盘点全量原稿。

每条目录记录须至少关联来源位置、原文/版本、适用模式、同名关系、能力机制、依赖原语、争议与实现状态。界面将当前自定义预组与官方派系分开；颜色和官方名称以专人原稿证据绑定，未实现的覆盖明确显示。只有卡片全部相关文字、费用、目标、时点及离场规则有执行路径才开放，不靠名称分支或仅展示牌名。

## 候选依赖顺序

此顺序随完整目录的实际依赖调整；每批先选少量真实原卡核实共享原语，再扩展同类整卡。

| 阶段 | 共用能力 | 首批证据样例与验收要点 |
|---|---|---|
| 0 基线完成 | 立即/可响应策略、版本兼容、提交回执 | JC042；新核实际UI定点、原四人房续测到终局或实际阻塞。历史错误窗口不当作正式规则证明 |
| 1 已有原语覆盖 | 现身触发、地区/暗藏者目标筛选、消灭、目标复验 | JC058原卡可复用`Reveal + Hidden/Any/SourceRegion + Destroy`；付费现身或潜伏改变对象后，旧目标失效；费用不回滚 |
| 2 有效属性及修正寿命 | 印刷值与当前值、来源、控制修正、优先顺序/到期 | JC129暂时控制与回合末返还；控制、所有者、费用支付者分别记录。顺序争议待正式解释/定点评审 |
| 3 区域与私密访问 | 牌堆/墓地来源、合法区域施放、检视与选取/排序 | JC085墓地施放、JC057受限检视；每个授权玩家仅看到其获准信息；等待选择可精确恢复 |
| 4 关联区域 | 附件、封印、宿主关联、离场清理与返还 | XQ40封印后宿主离场回所有者手牌；JC036附件控制；JC066仅读取封印牌的印刷图标，不能复制其他效果取得的图标 |
| 5 对抗与结算扩展 | 声望参与、图标修改、伤害要求、取消及堆叠交互 | JC070声望等，以所选版本原文决定参与范围。检视/终止堆叠等依赖先补齐，整卡通过后开放 |
| 6 依赖闭包扩展 | 已验证原语组合及合法混合构筑 | 按全面目录覆盖当前模式适用卡。跨重印同名限制、忠诚/资产颜色与秘社限制依原稿校验；保留未实现及争议列表 |

跨批发布须保留活跃旧房的确切规则身份及恢复。若更改schema或引入新内核版本，先说明兼容方案、运行中房间影响和部署预算，再实现并核实；不能累计未知版本或静默迁移。当前双核仅覆盖已发布v0.2.1/v0.2.2，不宣称已解决无限版本保留。

## 每批开放门槛

1. 原稿位置与实际原卡文字已核实，能力拆解到共用机制；冲突卡隔离。确有规则争议时做定点Astra max评审，保存依据与裁定，缺证据不能猜测。
2. 有意义的原生规则测试涵盖正常结算、费用失败原子性、目标失效及该原语的关键交互；实际WASM状态/玩家视图对照通过。
3. 等待选择、效果队列/堆叠、控制/关联等中间态保存恢复精确；同commandId返回原回执，不重复费用或效果；未知提交不伪造成功。
4. 玩家投影视图只暴露获准的手牌、暗牌、检视内容；临时访问结束后不残留给无权玩家。真实UI能够选择、分配/排序、理解等待对象和失败原因。
5. 使用2–4个独立云端界面，以不同派系或合法混搭持续实玩；各操作者只用本席信息制定策略。记录核心牌实际见到/使用、联动、非让过行动、等待耗时及可复现错误，修复后在原场景复测。
6. 分阶段私有commit/push保留成果；同Site在兼容检查后发布。部署状态、实际体验与未通过门槛分别记录；卡池计数不代替行为验收。
