## 确认问题

### R1 · P1：CQ28 磨牌遇到传闻，会拒绝正常的最后一次响应 pass

定位（均为固定 HEAD）：`rust-game/src/import20_gate.rs:419-420`；`rust-game/src/rumor.rs:512-560`；`rust-game/src/exposure.rs:656`；`rust-game/src/engine.rs:657-683`。

真实可达场景：玩家处于正常行动步骤，拥有四个黑色资产、CQ28 手牌；牌库前六张含 WM042，场上有一个可成为传闻封印目标的角色。WM042 的传闻不要求秘社隐秘标志。正常 `play`，选择“磨六张＋磨六张”或“磨六张＋抓一张”，支付四费，所有玩家正常响应过让。

CQ28 的第一个模式调用 `mill_cards_with_cause`，保留的原操作是 `CQ28Mode { mode: 0, ... }`。遇到传闻牌后会生成正常 `ChoiceResolution::Rumor`。但传闻批次校验的 `allowed` 分支只承认 `IndustryMill`、`MoveDeckTopToGraveyard` 等有限操作，没有 `CQ28Mode`，因此返回“传闻原效应不能产生该区域转移批次”。`Game.apply` 的后置 `validate_exposure_state` 会调用该校验，导致最后一个合法 pass 回滚，已付 CQ28 留在原响应堆叠，无法沿这条正常路径推进。即使玩家本来愿意放弃传闻，也无法到达该选择。

这不是额外损坏存档扩测，而是 CQ28 已接入通用磨牌后遗漏正常续体准入。原图与手册的传闻规则要求入墓前可替换为封印。CQ28 的 16 个现有单元测试覆盖重复与混合模式，但已知牌库不含传闻牌，遗漏此交界。

建议：只在认证完整 CQ28 帧、当前磨牌模式、原玩家和至多六张原批次的条件下接纳该 cause；同时覆盖磨＋磨、磨＋抓，传闻接受/放弃、连续多张传闻以及后续模式只执行一次。不得泛化放开任意 Op。

独立反例源码：`cq28-rumor-repro.rs`。已实跑：磨＋磨、磨＋抓均在正常最后 pass 报上述真实错误；探针在失败前还确认已支付四费，且拒绝前后序列化状态完全一致。没有合法封印宿主的磨＋抓对照通过。使用期待正确玩法的断言保留了两个红色失败，没有把当前错误包装为通过测试。

### R2 · P2：同控 WM057＋WM025、双 BQ039 同时触发，缺少本人排序选择

定位：`rust-game/src/mystic_hooks.rs:5`；`rust-game/src/mystic_contest.rs:320-324`；`rust-game/src/batch3_entry_order.rs:46-54`。

真实可达场景：同一玩家操控正面 WM057 和 WM025，用正常付二费、横置的 WM057 行动进行隐秘对抗；其队伍通过四席实际提交赢得对抗。本人此时同时产生 WM057“遏制/可检视”和 WM025“各有本方吸血鬼地区放势力”的触发。

观察器固定按 WM057、WM025 的顺序压入声明。随后虽然调用 `batch3_register_entry_order`，但该函数的 `introduced` 卡单没有 WM057、WM025；当这一组只有这两张时，条件为 false，不建立排序组，直接先给出 WM057 的发动/模式选择，不能选择先把 WM025 放入堆叠。这会限制玩家选择，且两种效果改变地区势力、赢区与目标存续时可能产生不同结果。

本地《隐秘世界规则手册》physical 4 / printed 2 原图明确规定：同时触发时，先后手分别决定自己触发入堆叠的顺序。`import20_broker_tests.rs:249-253` 检验最终只处理一次并断言排序组为空，没有证明玩家获得顺序选择。

同类遗漏还涉及 BQ039：它是非独有附属，两个本人 BQ039 可以观察同一实际获胜战斗。`engine.rs:1505,1535-1538` 只追加声明，战斗分支没有为这组触发注册排序；`introduced` 也没有 BQ039。已追加 `bq039-order-repro.rs`，以两次真实付费结附后 2:1 战斗获胜构造这个边界，已独立实跑失败：`pending=trigger`、首声明为 BQ039、另一个 Eye 声明仍在队列、`orderGroups=0`。完整结果另记 `independent-eye-execution.json`，本次追加只执行这一个新用例。

建议：将这些新观察器正确接入已有同时触发排序契约，保留实际 contest/event 键和本人权限，并验证两个入堆叠顺序；战斗的伤害/领取者队列顺序应保留。`trigger-order-repro.rs` 已实跑并失败：实际 `pending=trigger`、首声明为 WM057、WM025 仍在队列、`orderGroups=0`，期待的 `batch3-entry-order` 缺失。
