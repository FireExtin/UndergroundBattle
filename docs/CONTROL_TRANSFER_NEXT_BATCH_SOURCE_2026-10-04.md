## 对当前实现的最小差距

**共同复用**：Card.owner/controller、controller 队伍/图标/合法动作/暗藏授权、LC01 私有顶牌投影、JC008 按目标 instance 持续的回合修正、付款/响应帧/目标 guard、现有附属与离场/身份重置、持久化与日志重放。字段已经存在，不等于已经有合法夺控能力。

**共同新增**：当前 rules.rs::Op 无取得/交换控制操作，StaticModifier 无控制持续效果，model 无控制来源/期限/顺序记录。需要可序列化、绑定目标 instance 的控制效果与有效 controller 重算；单纯改 controller 后盲目在回合末改回 owner 不足以覆盖叠加来源。控制变更本身应保留目标 instance、位置和已有实例修正，且接入独有冲突/授权重算。

| 卡 | 可复用 | 特有最小差距 |
|---|---|---|
| JC129 | Standard 事务、EnemyTeam 角色目标、响应后复核、FinishCleanup 的回合末批次 | 新 GainControl 至回合末；事务本身结算入墓不应提前取消已结算效果；清理时与伤害/属性到期同批处理，恢复此前仍有效控制来源 |
| JC036 | AttachmentSpec、宿主验证、附属消灭/宿主离场清理 | 来源有效时由附属当前 controller 取得宿主控制；印刷人类限制与当前类别分开；人类→吸血鬼的动态类别替换，保留其他类别；附属失效后撤回其控制和类别效果 |
| JZ27 | Event::Reveal、SourceRegion 目标、角色部署/付费现身、独有队列 | 同地区当前人类目标；已结算控制与“加奴仆”类别效果绑定该来源 instance 的离场期限；不能把现身触发改成任意进场触发 |

**当前代码的具体边界**：resolution.rs 的 subtype 目标守卫及 attachment.rs 的宿主 subtype 检查都直接读取印刷 definition.subtypes，尚无当前有效类别视图。Op::Hide 调用 leave_board 与 fresh，生成新 instance 并保留 controller；未来不能仅凭 helper 名称把盖面等同所有控制来源真离场。需要明确目标/来源盖面和现身取得新 instance 时，控制是否继承、何时终止，避免永久遗留夺控或提前取消历史效果。JC008 实例修正已有边界，不能在新增控制时破坏它。

**父需依据原文定案**：多重控制效果的先后顺序及逐个失效后恢复哪一有效来源；目标或来源盖面/现身的新实例边界；JZ27 来源后续被他人操控时已结算效果的受益者是否改变。原图与本次实读规则页不足以替这些组合编造统一顺序。JC036 旧 FAQ 只明确孤立初拥被消灭时归拥有者，以及宿主潜伏使初拥消灭后暗藏者归拥有者；不证明有另一有效控制来源时也总归 owner。

实际查看的规则原页：霸权说明书 PDF16/印刷15（owner 不变、controller 可变、“你的/本方”按 controller、魔法领域及自身名称只指此实例）；PDF19/印刷18（潜伏/现身、唯一构筑一张）；勘误及释疑 PDF3/印刷3（上承初拥的两条说明）。FAQ 的基础编号是旧版编号，只按匹配名称/规则引用，不将其旧编号绑定到当前同编号的其他卡。
