# 交互语义与必须保留的规则疑点

证据缩写均按 **PDF 文件第几页，1 起算**，不是印刷页码。`BQ`=霸权说明书，`RM`=规则手册，`FAQ`=勘误及释疑，`PG`=玩家指南；扩展 JPG 直接按文件名。具体路径和目视范围见 [manifest](evidence/manifest.json)。本设计以霸权模式为当前规则包，其他版本不是默认补丁。

## 1. 响应、优先权与声明不是同一维度

BQ15：后进先出；双方让过后只结算一个顶项，再恢复优先权。建立资产、秘密派遣、持续能力、追加费用，以及产生资源或减少费用的行动不可响应。BQ17：来源离场不阻止已经产生的效果继续结算。

因此，`Timing` 决定何时可以提出声明，`ResponsePolicy` 决定声明后是否开响应窗；`ChoiceKind` 决定谁提供输入。这三者不能合并成一个“按钮类型”。LC19 的能力含资源/横置费用不意味着它不可响应；费用本身不可响应也不意味着所有含费用的能力都是 Immediate。

JC042 快速牺牲自己来减费，按 Immediate 执行。若费用牺牲同时产生独立死亡触发，该触发仍有自己的可选性和响应政策。现有 `disciple_reduction_on_empty_stack_is_immediate_and_restores_without_repayment` 与 `immediate_policy_keeps_cost_death_trigger_responsive_and_choice_resumable` 应保留。不要为了统一队列而恢复旧的减费响应窗口。

2V2 的一方优先权由两位存活玩家共享：本方每人都让过才切换；任一队友行动重置相应 pass 状态。付费、目标中的“本方”、使用次数仍归固定行动者。不能让队友替付费用或在来源被对手操控后把旧帧 actor 换成新操控者。

机动是独立调度政策：先手方的移动完成后再处理后手方（BQ19）。一般同时触发则是先手先放、后手后放、按栈反序结算（RM4），不能因为当前 Mobility 特殊流程有效，就把所有触发都逐一完全结算后才声明下一项。

## 2. 目标、范围和来源快照

声明先选合法目标再付款；结算时原目标消失或失去合法性，整张牌/能力不生效且费用不退（BQ4）。这支持当前单目标 guard。多目标卡尚不能推导成“仅忽略非法目标，其余照做”；必须找该卡与规则包的原文后才放开多槽。

三种引用应区分：

| 引用 | 何时绑定 | 例子 |
| --- | --- | --- |
| 目标实例 | 声明时；结算一次复核 | 对暗藏者的目标在其现身后失效；同名新牌不是原目标 |
| 来源/事件快照 | 声明或事件时 | 费用牺牲来源、LC23 来源响应中离场后仍横置目标；FAQ3 来源原地区案例 |
| 当前状态查询 | 执行该 Op 时 | 当前操控权、有效防御、谁仍在场、效果中后续选择的候选 |

现在 `SourceRegion` 总读快照适合部分已核验案例，但不是所有“本地区”语句的通则。给每个能力明确 `RegionAnchor::{SourceAtDeclaration,EventLocation,CurrentSource,ChosenRegion}`。来源移动后原地区还是新地区、手牌来源的“本地区”指何处，未核准就禁用对应卡/组合。

LC23 的横置自身与横置目标均在效果中；自身已横置不是费用失败，也不能阻止宣告。来源已经离场，目标仍合法时，目标的横置部分继续执行，现有测试已经覆盖。与 JC003 的“付 2 + 横置来源”为费用的情况必须分开。

效果一旦 guard 接受，随后由该效果移动目标并暂停选择，恢复不能再次从初始 guard 取消整帧。接受的是“这次开始结算的合法性”，不是把目标以后的全部属性冻结。

屏障影响敌方指定目标；范围选择或效果让某玩家自选牺牲，不可一律当作敌方指定。目标槽与 `ChooseFromSet` 必须分别建模，避免 UI 和后端误把一切点击都叫“指定”。

## 3. 连锁死亡、观察者和触发排序

BQ10 的战斗伤害先分配、同时造成；FAQ4 不允许在分配后、造成前任意插入普通快速行动。RM12：被防止到 0 就没有造成伤害事件。由这些约束得出的事件结构应是：

~~~text
DamageIntentBatch [source, recipient, amount, reason, batchId]
  → 已核准的预防/替代与将发生事件处理
  → DamageAppliedBatch（仅实受 > 0 的分量）
  → lethal wave 1（同波名单先固定）
  → 重算持续属性 → lethal wave 2 ...
  → 事后触发收集、玩家排序、按政策入栈
~~~

JC059 光环被牺牲后，受伤角色失去防御而死是第二个稳定化结果，不能等到下次轮询或下一回合。现有 `settle_deaths` 反复扫描是正确起点，但它把死亡声明按队伍/座位排好并不能替代 RM4 规定的“同一玩家决定同时触发顺序”。

后续补核 JC059 原图还发现一个当前缺陷：它给本地区的“其他友方角色”加防，`engine.rs:270` 却只认相同 controller。2V2 同队不同座位的角色应纳入原文友方范围；修正不需要等待完整持续系统，但查询接口必须明确 Self/Friendly/Enemy/Independent，避免未来再次误用。

建议 `EventBatch` 保存发生前快照、实际结果与波次；`TriggerBatch` 保存来源、事件、actor、是否强制、已选顺序、已声明项。可选触发允许放弃，强制触发不提供“取消发动”；有目标但无合法目标时，如何处理仍按能力规格。

以下不是已裁定规则：同批即将死亡的旁观者是否看见其他对象死亡；同一事件上跨队友的排序由谁决定；死亡触发与连续约束失败触发之间的通用顺序。现有代码固定 seat 顺序只是确定性实现。需要卡级证据或裁定；不能把 APNAP、主动玩家任意排序、时间戳优先从其他游戏搬来。

## 4. 替代、预防与“将要”触发

至少分四类：

- 连续预防：霸权把灵体标为持续能力，按所在地区双方的有效领域图标数量条件防止全部伤害（BQ19）。不是全场领域或领域种类数，不能把地区外资产供忠诚的数量带入。通用手册 RM8 标为触发，不能混用；当前霸权规则包选择霸权分类，若引用旧产品卡另记录适用性。
- 明示替代：文本明确将一个事件改成另一个事件，例如遭遇离场/潜伏改洗世界牌库（序曲）。替代后的事件不应同时当作原移区发生。
- 将发生事件触发：JC077 明印触发标识，另一名本方非灵体角色将受伤害时，可以把伤害转到自己。它不是指定目标，也不是“自动按防御最优分摊”。
- 事后触发：实际造成伤害/死亡之后才观察，不能回头把已发生事实取消。

JC077 是最需要先定的复杂边界：卡面能支持挂起 `DamageIntent` 并让操控者决定，但没有足够通则决定多个庇佑圣灵、来源在该触发响应中离场、转移后灵体防止的重评次序、同一伤害是否可重复转移。建议先实现可持久化的 ProspectiveEvent 框架和确定场景，**这些组合保持禁用**；不能把所有“将要”都静态当替代，也不能给战斗分配和伤害之间凭空开普通自由响应窗。

护盾（BQ19）是敌方把牌当目标时的强制触发，消耗标志并终止来源效果。当前 `shield_stops` 在结算 guard 内扣盾，只有测试造出的 shield，没有生产获盾牌。此行为不是完整护盾规则；目标声明时机、多目标一次还是多次消耗、被终止的是能力还是实体卡、多个盾的排序需补齐后才开放。

传闻在霸权/帷幕之后同时印着“触发”和“改为”，需要保留这种原文组合，不应凭术语把它挪到任意死后事件。转生则相反：WM071 原图写进入墓地或被封印时洗回，**没有“改为”**。目录多写的词会决定死亡是否被观察、封印是否建立、费用是否完成；不允许据此直接实现替代。

费用牺牲遭遇或转生牌时，若目的地被改变，算不算已支付？目前原文不足。框架能表达，但不能把框架可表达当作裁决已经存在。替代规则使用有限 applicability / priority 数据，并记录同一事件已用的替代来源防止循环；“每个来源只用一次”本身若改变合法结果也需明确规则授权，不能暗中作为裁定。

## 5. 宿主、拥有权、操控权与形态

| 转换 | 身份/可见性 | 宿主与事件后果 |
| --- | --- | --- |
| 场上横移 | 同一次实体；保留横置与标志 | 进入地区，不是重新进场；附属跟宿主，不独立移动（FAQ5） |
| 潜伏 | 旧目标失效；隐匿信息按权限 | 视为离场；附属消灭，封印回拥有者手；保留横置状态（BQ12） |
| 付费现身 | 先上堆叠，不能再作为在场暗藏者被指定（FAQ3） | 成功后进场与现身事件；保留原横置状态；仍付费用/忠诚 |
| 效果现身 / 闪烁 | 明确 RevealMethod；无额外付费除非文字要求 | 闪烁是一个效果内先潜伏再现身；不能插普通响应，但产生的事件不消失 |
| 转变 | 原对象换 FormId | 旋转 180°，不是横置、潜伏、现身或进场；不自动清标志/重置（间奏） |
| 结附 | 对象在场，多类型仍一个实体 | 不继承宿主操控者；持续检查结附合法性；允许合法的嵌套宿主，拒绝环 |
| 封印 | 不在场、空白、通常双方可查看，不可普通指定 | 宿主离场/潜伏回拥有者手；不同于附属送墓（BQ16/RM6） |
| 控制变化 | owner 不变；有效 controller 变 | 旧能力的 actor 不变；后续目标合法性用新控制；是否移区/换宿主没有通用隐含效果 |

控制授予应保存来源、有效条件与结束条件，来源失效后重新计算；不能在所有来源离场时都粗暴“交回 owner”，因为可能有其他控制效果仍生效。重叠授予优先次序未裁定时禁用组合，不用最后一条修改覆盖。

宿主清理还有一个已核的特殊整批场景：BQ10 赢区流程明确把角色、暗藏者、附属都送各拥有者库底。须先为整个批次确定目的地，不能因顺序移走宿主把同批附属改送墓；所有牌的回底顺序由拥有者选择。封印不在场，不属于这批在场牌；其宿主离场的处理另外适用。若某张具体牌的撤回/替代与这些批次规则冲突，先补该组合裁定，不允许底层容器遍历顺序替玩家裁决。

血液结附（JC028）是类型/属性覆盖与宿主赋予。先牺牲费用已产生自己的事件，再用该次付款的 after 引用尝试结附；这是第一个检验 PaidTransfer 是否充分的实例。饮血的“墓地或秘社封印”是受限选择源，不代表所有封印都能任意指定。

## 6. 临时属性、派系混搭、2V2 与构筑

颜色、秘社徽记、领域、类型、子类、牌名是独立过滤轴。忠诚按资产颜色/领域的实际数量检验，横置资产仍供忠诚。JC070 的费用 1、白忠诚 2 说明不能从费用推断忠诚。LC15 五领域说明不能用单个 domain enum 代表全部领域图标。

构筑先应用模式的基础规则（PG14 至少 50、通常同名最多 3，允许混色），再应用所选秘社的具体限制和牌面例外。不能从官方基础两色配对推荐或当前五套自定义预组推导“只准这两色”。同名跨版本的数量限制与原图版本身份分别核验；生成指示物、转变面、世界牌不作为额外可选玩家牌。

唯一（构筑一张）、独有（金名，在场同名限制）、领袖（同一玩家控制最多一名领袖）是三种约束。独有需要控制变化/名称变化/形态变化后也检查；不能只在正常部署后安排一次 `Unique`。BQ19 已明确：另一名领袖在该玩家操控下进场时，选择并牺牲其中一个。因此进场冲突不用等待新裁定；由控制变化、授予领袖或转变形成的非进场冲突，原页没有同样明确的处置时点，须另核。

BQ22 的 2V2：两侧各两座位、五地区、共享先后手/优先权和势力、胜利 10 分；一般部署仅自己最近三地区；机动只相邻；效果直接放入地区不受通常部署距离约束，法术/附属也没有统一距离封锁。`本方` 是本人，`友方` 才包含队友。队友手牌和暗藏者不会因同队自动公开。

调查/战斗奖励由有贡献的队友中按模式选择接收者，费用和手牌仍个人；特权也须符合贡献资格。隐秘对抗是队伍合计比较，胜负后个人标志选择按霸权原文处理，不把团队结果等同于任意队友代选私人牌。

经典指南 PG21 的对坐队伍、轮流个人行动、12 分以及由先手决定顺序，不能塞进此霸权 ModeProfile。同理，霸权赢区应先各牌回拥有者牌库底，再拿取地区/补区（BQ10）；现有顺序符合霸权。RM12/PG14 的经典流程先拿区再回牌，不应据此“修正”霸权。

## 7. 牌库、随机与同时动作

抽牌只用于明确“抓/抽牌”；JC049 底牌入手、隐秘对抗顶牌入手不是 Draw，不应误触发抓牌观察者或牌库不足淘汰。检索资格由规则筛选；是否可失败找不到/主动不找、是否需展示、洗牌时点逐卡给出，不能套用别的 TCG 的搜寻通则。

DQJC116 香港：所有玩家各检索一张附属，**同时展示并加入各自手牌，再洗牌**。当前没有生产附属，老检索逻辑不能证明此卡正确。需要 `ChoiceGroup` 收齐个人选择后统一执行公开批次；不能先公开第一人的选择，让后提交者据此改变选择。

选择屏障与原子事件批次分开：前者跨多条命令等输入，后者是在一个规则时点一起发生的事实。每人选牌期间不推进牌库状态，也不开普通响应；可持久化已提交选择，其他人最多看到允许公开的“已选/待选”。是否允许自己撤回，应在产品交互中明定，默认提交即锁定，不能因网络重试替换已经接受的选择。

随机只来自存档 RNG：混乱进入地区，洗牌，初始先手，任何随机弃牌等都经过同一个确定性接口。在同时组最后一人完成时，按稳定座位/事件顺序消费 RNG，不能按网络到达顺序消费。空合法集合时不能 `random_below(0)`；是效果失败、保持原区域还是禁用声明按规则规格处理。

隐秘对抗先收所有人的手牌选择，再同时展示，用印刷费用和专门修正比较，随后把所选洗回牌库（BQ20/BQ22）。手牌选项属于本人，队友也不能预览；恢复时不能重新抽取已展示牌或重新洗牌。隐秘/暴露抵消及手牌上限是状态规则，不是普通势力，星光的“更多隐秘或更少暴露”也不能随意换成一个未证实的总分公式。
