## 最小牌组的实际校验

上表最后一列合计 25 张黄色牌，再加入 `JC125 无知路人 ×25`（中立、已审不限副本例外），恰好 50 张普通牌。9 种黄色牌是当前每名最多 3 张条件下达到 25 张的最少种数；10 种普通牌是这个示例的最少条目数。秘社额外选择一张，不计入普通牌 50，也不计入普通牌的黄色 25。

实际调用三个原核的 `newGameWithDeck`，只生成本地新大厅：

| 校验输入 | 实际结果 |
| --- | --- |
| 各版所有黄色牌满编，JC125 补足 50，`societyId:null` | 三版均接受普通构筑 |
| 同上，选择已开放 MSJC09 | 三版均接受秘社牌组 |
| 同上，选择 MSJC01 | 三版均拒绝：`未知或未开放秘社：MSJC01` |
| JC008 候选的 25 黄 + JC125×25，不选秘社 | 接受 |
| 同一最小普通牌组，选择 MSJC09 | 接受 |
| 同一最小普通牌组，选择 MSJC01 | **仍拒绝：未知或未开放秘社** |
| 减少 JC125 至 24，普通牌共 49，选择 MSJC09 | 拒绝：至少 50 张 |
| JC008 增至 4 张并保持普通牌共 50 | 拒绝：灵能激发同名最多 3 张 |

因此，现在不存在“已经通过服务准入的 MSJC01 最小合法牌组”。存在的是实际通过普通构筑、满足原图数量要求的未来 MSJC01 输入示例，以及实际通过已开放 MSJC09 的秘社控制样本。交接中的 `minimum-25-yellow-50-MSJC01-unadmitted-draft.json` 明确为未开放输入，不是可导入开局的已准入牌组。

另把当前 `society.rs::validate_construction` 函数逐字提取到仓库外的只读 Rust 探针，用未注册资料值 `MinimumColor { color:"黄", count:25 }` 调用它。三份普通牌组先通过真实 Native `deck::validate`，然后原有颜色约束拒绝 24 黄、接受 25 黄和 27 黄。没有修改原函数、添加 registry 条目、开启 `society-fixtures` 或改变服务准入。该结果只证明构筑约束可复用。

复用时颜色应使用现有 catalog 的规范值 `黄`：后端颜色计数是精确字符串匹配；前端才会去掉末尾“色”。不要把忠诚数组中的 `黄色` 当作构筑颜色字段。副本是按印刷名称累计，而非逐卡号分别放宽。

## 最小机制设计及待裁定边界

可直接复用：

1. `SocietyDefinition`、6 张起手、每席非地区 `societyZones`、不可离场、deck snapshot 和构筑检查；现有 `MinimumColor` 可表达 25 黄。
2. MSJC09 的标准时机、`Cost::Assets(3)`、`Cost::ExhaustSource`、`DrawIfActorHasInitiative`。条件在付费 Frame **结算时**按发动者当前团队是否持先手检查，后手合法发动会支付而不抓牌；四人沿用已审团队先手语义。不能另把它变成声明前资格条件。
3. 第二个能力的 `Cost::Assets(4)`、`Cost::ExhaustSource`、具体 `abilityId`、响应 Frame 和既有 `Search { player:Actor, to_top:false }`。既有搜索私下给本人完整选择，选择后公共日志展示牌名，新 hand instance 入手，洗剩余牌库，并可通过待选持久化恢复。检索没有印刷“目标”语句，选择应在结算时进行，不是付费前指定目标。

需要两个有限增量，**本轮没有实现**：

- 一个“印刷颜色为黄且 `unique:true`”的联合过滤；不是 `keywords:["唯一"]`，也不限定为角色。现有 `Kind`、`SocietyOrMagic`、`PrintedCostAndSubtypes` 都不能表达它。继续复用现有 Search/Frame，不另建搜索执行器。
- 每局一次的声明资格和持久化使用记录。建议绑定稳定秘社来源及能力 key，在一次合法声明付费成功时原子消费；未付费/被拒绝的命令不消费；已付费后的空检索或响应不能退还；横置重置、换回合、重复请求、待选恢复和日志重放不能再次消费或清除，只有重新开局清除。这是提交裁定的项目方案，未发现原文逐项定义所有失败边界。

供下一次裁定的两个问题：一次额度是否按上述“合法付费声明”消耗；无黄色独有命中时，是否沿用当前 Search 的“允许付费发动、洗牌并记录无命中”行为，还是声明前关闭。原牌允许检索黄色独有，但没有直接规定空命中资格；现有代码在无命中时会洗牌并记录，选择是否可拒绝也需与既有检索解释一致。没有通过扩大卡池或改过滤制造命中。

新增使用记录将影响私有持久化契约，需要未来版本隔离、回放/恢复/重复请求及新局重置测试。前端已有秘社来源和多 `abilityId` 路径；公开的已用状态如果需要，应先提出最小契约再实现。现有 `unresolved_abilities` 可隔离尚未裁定的能力，但本轮没有开放整张 MSJC01 或其中任一能力。
