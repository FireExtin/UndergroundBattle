## 最小可确认布局

1V1先保持整张桌面：对手玩家区在上、三地区与其两侧角色在中、自己的玩家区和手牌在下。世界牌库靠中线左侧；玩家牌库/墓地作为各自的一对牌堆，资产以实际卡牌排列并显示横置；计分牌和先手标志有固定位置。右侧或角落仅放当前响应堆叠/待选的临时层，不能将角色移出所属地区以换取面板排版。具体俯视或轻透视、卡牌尺寸与桌面材质等等待用户确认。

2V2沿用同一桌面结构，中央改五地区；两名队友同侧、各有独立玩家区。四个所有者标签及其费用、牌堆、得分保持独立，团队合计另列。左、右席位与五地区对应关系必须保留；本人看的是自己的手牌，队友只显示牌背/张数。显示视角如何交换上下或聚焦本人，要先明确而不能改变地区编号和可达范围。

## 与当前权威视图的对应关系

| 原图区域 | 当前视图/引擎已有的数据 | 显示边界 |
| --- | --- | --- |
| 三/五地区及双方争夺区 | `regions[index]`、其`characters`/双队`influence` | 每张角色留在实际所属地区；拥有者和操控者分别保留 |
| 玩家手牌 | 本人`hand`；其他玩家`handCount` | 包括队友在内只展示本人手牌身份；他人用牌背数量 |
| 玩家牌库 | `players[].deckCount` | 牌堆背面+数量；不显示顺序或身份 |
| 墓地 | `graveyard`按`owner`划分 | 双方公开可查；每位拥有者独立牌堆 |
| 资产区 | `assets`按`controller`划分、`exhausted` | 显示实际牌色/领域及横置状态；成本与忠诚是两回事 |
| 计分区 | `scoreCards`按`owner`划分、`players[].score` | 1V1独立分；2V2保留个人计分牌及团队合计 |
| 先手/行动权 | `firstTeam`、`priorityTeam`、`activeTeam`、`legalActions` | 先手不等于当前行动权；当前可行动席位由服务端决定 |
| 世界牌库 | 引擎`Game.world`已有，当前`View`未导出剩余张数 | 不能从同名地区或墓地猜数量；布局可先用明确世界牌库背面位置，准确数量需经批准添加公开字段 |
| 秘社区 | 当前没有可玩的秘社牌或其能力 | 五套自组预组不是秘社；保留区域时明确未开放，不放伪造可用能力 |
| 正在结算的牌/能力 | `stack`、本人`pendingChoice`/他人`waitingChoice` | 临时响应层有来源、目标和结算次序；他人不看私有选项 |

源码证据：`rust-game/src/engine.rs`的`team()`以seat/2分队；`accessible()`令偶数席位进入index0–2、奇数席位index2–4。即p0/p1同队、p2/p3同队；p0/p2是左席，p1/p3是右席。不能为了视觉顺眼把队友牌或控制权合并。

## 当前未决

用户尚需确认视角、电脑横屏/手机优先及最小布局草案。当前微调没有解决其“非常不好玩”的反馈；两名独立试玩者正在记录规则操作与界面问题，不以规则测试通过替代桌面体验认可。原图只留在私有云端，不上传公共Site。
