## 4. 完整机制契约

### 4.1 进场、可选性与无目标

1. 定义事件为 `Event::Enter`，不能使用 `EnterRegion` 或仅 `Reveal`。手牌正面打出成功、付费现身成功、已准入卡牌效果放置进场都可触发；普通横移只进入地区，不再次触发。秘密派遣及建立资产不发动角色能力。
2. 成功进场时捕获 actor、来源牌实例、owner、controller、原槽位及原地区 UID。只生成一份可选声明，不在打出时提前转换。
3. 玩家选择接受或放弃；没有额外费用、横置、目标、数量、模式或每回合限制。即便当前没有敌方势力，也可以接受，响应可能改变结算时状态。不得把零标志作为没有进场事件或不可发动的先决条件。
4. 接受后进入可响应堆栈；各存活席按现有团队优先权让过，才结算。队友不能替 actor 接受/放弃，客户端自动让过不能代替这次选择。
5. 本地区只是作用范围，不是目标。`targets=[]`；不弹地区/玩家/标志目标选择，不触发目标屏障、护盾检查。单卡效果开始结算后，不在“移除”和“放置”之间开放普通响应或第二次选择。

### 4.2 势力转换

按第 2 节的原地区项目语义，推荐新增一个无参数固定操作：`Op::JC095ConvertEnemyInfluenceInOriginalRegion`。它只允许出现在 JC095 的精确印刷程序中，不引入任意标志转换 DSL。

概念伪码如下；这是设计，不是已实现代码：

```text
检查来源冻结的原槽位仍有同一地区 UID 且非空位；否则无效果。
friendly_team = team(frame.actor)
enemy_team = 1 - friendly_team
N = 原地区当前的 influence[enemy_team]
若 N == 0：完成本效果，不新增 Award。
把该地区 influence[enemy_team] 设为 0。
调用 place_influence(frame.actor, 原槽位, N)。
```

- `N` 在该操作结算时读取，等于这次实际移除数量；不在进场、声明或入栈时冻结。响应中敌方从 2 增到 3，转换 3；响应后变成 0，转换 0。
- “所有敌方”作用于该地区整个敌队共享池，不能按敌方两个席位各算一次。“本方势力”写入 actor 所在团队的共享池，不能在数据上创造个人势力池。
- 先移除后放置：合法状态中 `[本方0, 敌方N] → [0,0] → [N,0]`。不要仅调用 `place_influence(N)`，那只会抵消成零；也不要偷换为 `place_influence(2*N)`，它跳过印刷的实际移除步骤。
- 本方已有势力且敌方为零时，原本方势力保持；不清空两队，不把地区总量当作敌方数量。合法场上两队标志不能共存，不能用一个违反该规则的混合计数 fixture 冒充自然局面证明。
- 不封顶、无最低一枚、无只移一枚或只针对一个玩家的改写。最终放置使用原有抵消/阈值入口，避免旁路得分与地区清理。
- 采用一个原子操作，无“已经移除、等待补入”的持久化中间态或新 `FrameChoice`。未来若新增势力移除预防/观察者，必须再审该顺序，不能凭本次原子实现反推未准入卡的规则。

### 4.3 领袖、独有与来源独立

`jc052::printed_leader` 从运行卡面关键词读取；`leader_instances` 按当前 controller 筛正面在场角色，不按名称、owner 或团队筛。加入正确元数据即可接入，不需要新的 `Traits::leader` 或第三套独有机制。

- 同一控制席的 JC095 与 JC052/JC037 属于真实异名领袖冲突，必须选牺牲一张；各在不同地区仍冲突。
- 队友各控制一张不冲突；隐藏的 JC095 不是领袖角色。由别席拥有、当前由该席控制的 JC095 算该席领袖。
- 沿用先冻结进场事件、再强制领袖牺牲、然后可选进场声明的已有顺序。若新入场 JC095 被牺牲，其已满足的进场声明仍存在，且归原 actor；不能因当前找不到来源而删掉。
- 原 actor 选择牺牲自己控制的领袖，卡进 owner 的墓地。三名以上领袖沿用每次牺牲后再次检查，不能只减一次。
- 金名同名独有限制仍在。现有领袖优先于同名独有检查，不另外为同一对牌牺牲两次。领袖检查不是指定目标，不被屏障/护盾阻止。
- 来源在响应中潜伏、回手、死亡、移区、转控不转移已声明转换的 actor。源牌保留原实例的控制变化与离场后同名新实例必须区别；新实例没有权利替换旧帧来源。

### 4.4 声望与赢区

`Definition.traits.renown=true`，复用 `renown.rs`；完整定义同时包含进场能力。不能只加进场转换、遗漏印刷声望。

- 地区所有对抗结束时，按当前控制队统计该地区正面、未横置、未淘汰控制者的声望角色；不要求有过去参战记录，平数无奖。
- 多个同队角色仍只生成一次可选奖励，使用已有首个合法控制席；放弃后不逐张继续询问。两个队友各控制一名 JC095 是可达的真实多声望案例。
- 源离场不取消已经声明的声望奖励；奖励使用其自己的冻结 actor/地区 UID。该奖励和进场转换是两种独立程序，均需恢复校验。
- 普通势力奖励先 `Award`，旧地区已进入 `Window::Win` 就不再声明这次声望。补位地区不能吃旧地区的 `RegionConfrontationsEnded` 或旧奖励。
- 霸权原页标题为“赢取一个地区后的流程”：达到阈值之后才有快速窗口。现有 `WinContext` 保存赢家，重复 `Award` 对同一地区实例不重开窗口。**JC095 在敌方已经赢得地区的窗口现身并转换标志，不改变既定赢家**；回底、计分与地区赢取触发继续归原赢家。
- 因两队势力不能共存，通常未赢区的合法状态中，敌方 `N < threshold`，转换仍是 `N < threshold`，不会凭空立即赢区。把敌方直接摆成超阈值、又没有已有赢区上下文的 fixture，只能称阈值原语测试，不能宣称普通转换自然夺区。
- 合法的完整推进链可用：转换敌方两枚为己方两枚 → 后续势力对抗/声望补足阈值 → 正常赢区流程。赢区时 JC095 没有撤回，按拥有者回底；不能因为是领袖而留场或自动回手。

## 6. 恢复与非法输入守卫

除正常运行外，`Game::from_persisted`、Room 恢复与执行入口都必须保持相同封闭契约：

- 来源定义必须为 JC095，实例非空，actor/owner 在范围内，冻结 `source.card.controller == actor`；触发快照正面且无 `play_source`、附属宿主或死亡观察者字段。原槽位与原地区 UID 必须有值，但原地区或来源现在已消失不应被误判成非法存档。
- 若冻结来源 UID 当前仍存在于任何可保存实体中，其不可变 definition/owner 必须相符；参考 JC052 已修复的场上、手牌、资产、墓地、世界牌、地区、封印、附属、堆栈及待入墓实体检查。不要求当前 controller、位置、形态还等于冻结值。
- 付费部署/现身为精确空程序，支付记录保留真实资产 UID 且不重复，金额结构匹配既有资源/减费路径；不能以“费用7”硬认必须横置七张，因为资源与降费可能已经支付部分。实际资源/忠诚验证仍由通用支付流程完成。
- 进场帧只含一个固定 op，零费用、零目标、无 chosen_region，`cursor=0`、`guard=Unchecked`、step context 为 actor；不能保存已移除但尚未放置的半帧，也不能伪造数量参数。
- 堆栈 shell 的 controller、frame_id、卡牌、派遣地区、reveal 标志须匹配冻结帧。真实 JC095 card 配其他来源帧也要拒绝，不能只看 frame 内定义。
- 固定转换及付费进场帧不能通过持久化的直接 `Effect::Frame` 绕过堆栈；触发接受前只能存在合法 `Effect::Declare` 或 `ChoiceResolution::Declare`。运行时由真实栈顶转入立即执行队列与外部可保存的直接队列要区分。
- 可选声明是 `DeclareChoice::Accept`，min0/max1/allowDecline=true，唯一 accept 选项及固定标题/说明/座位全部校验；拒绝多余 target、mode、amount、previewCards 和伪改 player_id。
- 领袖强制选择直接由 `validate_jc052_state` 依据当下真实领袖组检查：min1/max1/allowDecline=false；删除全部强制检查或换成队友牌必须拒绝。无需复写一套并产生两种准则。
- JC095 印刷声望和既有 JC089 获授威名是允许的独立精确奖励程序，绑定其自身冻结地区。不得误杀合法奖励恢复，也不得通过改 key 为 renown 把转换移植进去。
- 减费、回手、控制或声望的旧能力不因本卡新增而放宽定义/帧验证。非法命令与恢复应原子拒绝，不扣费、不先清除势力、不推进版本。
