## 接入契约

父端统一负责以下共享挂钩：

1. `lib.rs` 注册红模块与测试；`rules::{ability,target,with_abilities}` 暴露 `pub(crate)`，定义表插入两张。
2. `TargetPredicate::XQ18CharacterOrAttachment`，目标保持 `Zone::Board + EntityKind::Any + Relation::Any + Range::Anywhere`。合法明置角色或合法公开附属可指定，排除资产、暗藏者、手牌、墓地、地区和玩家；继续复用屏障、护盾与结算守卫。
3. 四个有限 `Op`：`XQ18AddOneTimeToTarget`、`XQ18RemoveOneTimeFromTarget`、`JZ30AddOneTimeToOriginalSource`、`JZ30ForecastFrozenTime`。前两项只增减原目标 1，后两项只加原 JZ30 1 或预测冻结 X；不添加可配置标志数量 / X 解释器。
4. `rules` 调用 `red_time::{validate_ability,validate_definition}` 闭合完整定义及已选模式。只允许已有完整声望 / JC089 获授奖励例外。
5. `resolve_frame` 入口调用 `validate_red_time_frame`；预测 op 在游标推进后 `if self.jz30_forecast_frozen_time(&frame)? { return Ok(()); }`。预测暂停复用原有 `FrameChoice::Forecast`，无需新增排序容器。能力 / 状态验证及预测操作开始先检查实际卡实例与来源快照的目录准入，以 `Err` 阻断未知定义，不能在生成 `option / card_view` 时 panic。
6. `Game / Room` 存读、选择边界调用 `validate_red_time_state`。未执行原子帧只能游标 0 / 未检查守卫；仅 JZ30 的真实预测续体准入游标 1 / 已接受守卫，并核对选择者、冻结 X、实际顶牌、选项数量与全部绑定。
7. 共享 `death_observers` 承认任何已准入合法明置角色或合法附属的非零时间；死亡快照不限 JC045。离场、手牌、牌库、墓地、资产、暗藏者、地区、世界牌与实体出牌堆栈仍必须时间 0。不能删掉整个校验来绕过新合法状态。
8. JC045 持续势力用 `effective_time_markers` 聚合；JZ30 活体来源快照冻结同一聚合。JC045 来源和自死亡旁观快照仍保留相同的直接值，避免既有自身来源同一性校验错配。
