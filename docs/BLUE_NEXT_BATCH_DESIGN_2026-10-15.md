## 4. 完整效果契约

### 4.1 两条持续授予

建议新增有限查询 `has_mobility` 与 `bq035_grants_mobility`／`bq035_grants_combat_glory`，命名可在实施时按模块风格调整。所有入口先找到**当前在场的同 UID 实例**，不用调用方传入的旧副本冒充活体。

授予条件同时满足：

1. 受益者是当前在场正面角色，当前类别含吸血鬼。
2. 任意地区有至少一张正面在场 BQ035，完整定义合法，且它与受益者的当前 `controller` 相同。卡文没有地区限制；来源横置不关停持续效果。
3. 受益者当前有真实、正面、宿主合法且 `host_id` 指向其当前实例的附属：机动要求附属**名称准确为“鲜血”**；威名要求附属类别中有**装备或武器**，为“或”条件。

每种能力返回布尔结果。同名多附件、多位骑士、一个附件兼具装备和武器、以及印刷已有同能力，都不增加机动次数或同地区威名数量。本体不需要附件就有印刷机动和威名；自己的持续能力不能把自己的印刷能力变为有条件能力。

附属的颜色、owner、controller、领域和来源 ID 不是额外条件。XQ14 与 BQ040 都名为鲜血，都应支持机动；只有血领域但名字不同的附属不支持机动。JC089 毒血诅咒自身可授威名，但其名字不叫鲜血，不能误授机动。装备／武器不限于某个固定 ID，现有当前附属类型机制没有改变其类别时按印刷类别查询即可；将来引入附件改类再接当前类型查询，不能本批虚构泛化机制。

宿主获得屏障或护盾不会阻止无目标持续授予，也不会消耗护盾。已经结附的附件不因宿主后来有屏障而自动失效；复用 `attachment_host_valid` 的既有持续合法性，而不再次调用敌方指定目标检查。宿主移动时原 UID 不变，附件关系跟随；宿主离场／潜伏／封印导致附件正常清理。

来源离场、潜伏、变为资产、控制权改变，受益者不再是吸血鬼，或最后合资格附属离开／改附，都应立即重新反映当前能力。除已捕获的触发外，不留下永久授予、回合尾残留或幽灵修正。

### 4.2 印刷与授予机动

统一复用现有 canonical 机动程序，不能把动态能力永久写入受益牌的 `Definition`：

```text
key = mobility; event = ConfrontationStart
timing = Fast; response_policy = Respondable
costs = []; requires_ready_source = true
targets = [Region / Any / Any / Mobility，单个地区]
ops = [MoveOnBoard { entity: Source, region: Target(0) }]
无 modes、额外费用、once_per_game；保持旧机动的完整其余字段
```

- 行动阶段结束进入对抗开始时，先稳定当前场面，再一次性收集当时正面、未横置且有有效机动的角色。每个实例至多一份声明，同时有印刷与授予也不重复。对抗开始之后才获得机动或在该阶段才进入的新实例不补触发。
- 当前 `engine.rs::close_window` 和 `resolution.rs::emit_event` 都只读静态 abilities；两处必须一起接上动态资格。只扩展 `has_mobility` 或 UI 徽章没有实际效果。收集时冻结资格，不能先列 UID、等后一个声明被处理时才重新问骑士／附件是否还在。
- 延续现有先手队伍先移动、响应完整结算后再开放后手队伍声明的顺序；不把所有移动一次性直接执行。玩家可放弃；空选只放弃本次，不在同一回合移除再装鲜血后重开。
- 双人可去另一个仍有效地区；2V2 只能相邻且不可原地，不能环绕五地区首尾，也不受普通派遣“离自己近的三地区”限制。没有合法目的地时自然跳过，不制造无法完成的选择。
- 机动是自身移动。引擎用 Region target slot 承载目的地，不意味着把角色作为敌方指定目标；不向角色应用屏障或护盾。接受后正常入栈，响应先结算。
- 现有机动在排队声明处理时仍核查来源正面、未横置；已接受入栈后，响应仅横置该角色不会取消移动，横置状态随角色保留。已有 `mobility_first_team_resolves_before_rear_team_and_responses_resolve_lifo` 明确覆盖此行为，BQ035 应同契约。
- 已捕获的授予机动不因授予来源／鲜血离开而取消。接收角色死亡、回手、潜伏后产生新 UID，则旧实例不能移动新对象；仍在场但控制改变时，选择 actor 保留事件快照，移动保留当前控制权，不借机恢复旧控制者。
- 移动保持角色 UID、owner、controller、伤害、横置及真实附件；产生 `EnterRegion`，不产生 `Enter` 或 `Reveal`。例如 JC061 的入区能力可照常触发，JZ22／JC032 的单纯进场能力不能因横移重发。

**现有机动地区绑定的明确边界：**当前选择保存 `region:n`，`BoundTarget.region_instance` 为 None，范围从 `SourceSnapshot.region` 的原槽位判断。结算要求目的槽仍为有效地区；它未把该目的地区冻结为独立 UID。若同槽地区在响应中替换，旧实现仍解释为那个有效槽位；若来源被响应移到该目的地，则移动自然不执行。BQ035 先延续同型机动契约，并写回归；不能假称现有机动已有原地区 UID 守卫。如果实施要改为冻结目的地区实例或按结算时来源重算邻接，必须作为共享机动行为变更单独说明、覆盖 JC014／JZ45／JC061，不能仅对新卡暗改。

### 4.3 印刷与授予威名

`has_combat_glory` 增加 BQ035 本体的印刷资格和两条条件中的装备／武器授予，继续保留 JC018 与 JC089 独立路径。查询是当前资格，不以威名当作声望，不设置 `traits.renown`。

战斗获胜时，由现有 `renown.rs::jc089_combat_glory` 在伤害之前捕获当前真正参与且有威名的角色；隐藏、横置、战斗贡献为0、平手、失败和其他种类对抗都不触发。无敌方战斗角色或没有伤害／击杀也不影响威名。

继续使用固定 `jc089-combat-glory` key、`CombatWon`、无目标无费用可选声明、`PlaceInfluence { region_instance, amount:1 }`。历史内部 key 不表示只能由 JC089 触发，不需要另造“BQ035 威名奖励”并与旧威名重复入队。同队同地区多个来源和多个受益者合并一次；放弃后不让其他同队角色再选一次。

在战斗后响应中移除骑士、装备、宿主或改变控制，不影响已经捕获的奖励 actor 与原地区实例；同槽替换不奖励新地区。真实 `place_influence` 继续负责敌方标志抵销、阈值与胜区流程。角色另外通过 JC074 获得真实声望时，两种能力仍各在本来的时点生效，不能互相替代。当前实现与边界说明见 [JC018／JC089 威名修复](JC089_GLORY_BOUNDARY_FIX_CLOUD_2026-10-07.md)。

| 各卡专属 validator | 许多来源只允许自己的印刷程序及精确声望／威名例外 | 接受**已经由共享守卫完整验证**的 canonical 运行时机动；不能只看 key 放行，也不能漏掉非蓝色接收者 |

### 5.1 来源观察与程序形状分开验证

仅校验 `key == mobility` 或 op 为移动并不足够；但恢复时重新要求骑士／鲜血仍在场，又会错误取消合法历史触发。建议仿照已有死亡观察的有限事件快照，给 `SourceSnapshot` 添加一个默认空、只在授予机动事件生成时写入的窄观察记录（例如 `observed_mobility_grant`）。它不是用户可直接提交的行动参数，也不是持久化在所有角色上的能力标记。

记录建议包含：事件回合；接收者在事件时具当前吸血鬼类别的事实；当时真实 BQ035 的 Card 快照及地区；当时真实名为鲜血附属的 Card 快照及宿主 UID。接收者身份、操控者和原槽位已有 `SourceSnapshot`，不再复制一份。多个等价来源只选一个稳定见证，能力不计数。生成时从真实场面计算，不接受调用者自行填“有机动”。

恢复验证需要同时满足：当前规则版本支持该记录；接收者是准入角色、事件快照正面未横置；actor／controller 一致且席号合法；来源骑士正面、完整 BQ035、当时与接收者同 controller；附件正面、准入附属、名字鲜血、记录 host 等于接收者 UID；观察吸血鬼事实为真；事件回合与仍未结束的机动流程一致。若同 UID 现在仍存在，definition 和 owner 等不可变身份不得矛盾，当前 control／横置／所在区则允许响应改变。

历史观察是引擎生成的冻结事实，不是从当前场面重演整局。类似 `ObservedCharacterDeath.vampire`，它须支持事件后改类、附属及来源离场；不能为了检查动态类别而要求 JC036 或 JC030 的当时资产现在仍存在。文档和测试只能声称拒绝不一致、畸形及不支持的观察，不声称仅靠当前场面能证明任意人工改写整段历史的真实性。

印刷已有 canonical 机动的 JC014／JZ45／JC061／BQ035 不需要伪造授予见证，走印刷资格路径。没有印刷机动的接收者必须有有效的 BQ035 授予观察；不能把精确移动程序直接移植给任意角色。非机动事件和 frame 不得携带这个字段。

**这是建议的具体工程路径，尚未新增字段或实现。**若实施者能在现有 authoritative 事件上下文中提供等价的历史资格绑定，可保持较小序列化改动；必须证明同样的“合法离场后可恢复、无资格程序不可跨源放行”矩阵，不能只删掉当前资格检查。

### 5.2 入口与恢复全路径

1. **完整定义闭合。**只认 BQ035 的完整印刷机动加固定持续修正器；不允许删掉任何一条授予、修改本文的 own／team 范围、追加声望或其他 traits。只有已承认的印刷机动来源可把 canonical 机动写入静态 Definition；运行时授予不能变成注册表豁免。
2. **能力形状。**比较完整 `AbilitySpec`：事件、时机、响应策略、ready、费用、目标、范围、modes、次数限制与 op 全部精确一致。不能把 `mobility` key 配成 Draw、Destroy、PlaceInfluence、Immediate 或从 Target 移动其他角色。观察只能附于正确的 canonical 程序。
3. **声明与 pending。**队列来源／actor／事件观察一致；目标阶段为一个合法地区的可选选择，允许空选；拒绝变成 Accept／Mode、假目标列表、多选、重复选、错误席、旧 choice ID、过期版本及在错误窗口注入。恢复不能重新发事件或重复给同实例一份声明。
4. **帧与响应壳。**精确一个 `Step { context:actor, op:MoveOnBoard(Source,Target(0)) }`，一个匹配的地区绑定，无支付／模式／额外 chosen_region。尚未结算的可恢复帧应是正确的游标与守卫状态；不得借已通过 guard、追加步、跳过游标、`Effect::Frame` 直塞或伪 StackItem 绕过真实响应。合法内部临时执行形状与外部可恢复形状分开验证。
5. **目的地与实例。**严格解析 `region:n`，范围及公开摘要一致，不得越界、空槽或选择原槽；保持第4.2节已声明的旧机动槽位契约。源 UID 失效不能转移到同定义的新实例。威名则沿既有 `region_instance` 固定原地区，不与移动混用。
6. **运行与存读同守卫。**Game／Room 读回、effects 声明、pending 选择、stack frame、frame 分派及正常执行都要覆盖。不要只在专属测试中手工调用校验函数，或只有 `from_persisted` 受保护而执行入口漏检。
7. **合法跨卡接收者。**`rules::validate_ability` 以及来源专属 frame/state 验证目前有闭合白名单。必须逐个审计确实可能成为吸血鬼的已准入角色，覆盖 `blue_expansion`、`black_expansion`、`gray_expansion`、`red_time`、`jz22`、`xq37`、`wm023`、`wm056`、`jc052` 等相关路径及届时新增的 JC095／JC046。仅扩展 `jz22::runtime_ability_is_admitted` 不足以让其余守卫通过；它当前只接受两种精确奖励程序。
8. **回归不是放宽卡牌能力。**建议共享 mobility 验证器返回“这是一份已完整验证的合法运行时机动”，各相关来源验证器只对这一情形让行，其余印刷能力守卫照旧。非角色事务和附属不得因此获得移动角色能力，修改后的注册表依然拒绝移植。

来源快照也要按程序区分：现有机动收集器使用原槽位且 `source_region_instance = None`；JC052 等牌自己的进场程序却要求原地区 UID。不能因接收者恰好是 JC052 就把其进场帧必填条件施加给合法机动，也不能为了让其机动通过而撤掉进场守卫。共享机动分支负责自己的来源／历史观察契约，其他能力继续用原卡的严格条件；源快照的死亡观察、结附宿主、打出来源等无关字段不得夹带。

## 7. 交接结论

BQ035 已选为后续蓝色整卡设计候选，尚未进入实施队列准入。已确定的来源修正是蓝忠诚1；已确定的新增机制是动态机动事件捕获、合法历史资格及跨来源恢复守卫。威名应复用现有合并奖励，持续条件应复用当前操控者、当前类别和真实附属关系。

没有新增必须用户裁定的已知规则阻断。剩余工作均为可列明的实现、严格验证、真实命令回归和独立审查；不能因为来源可读或旧机动／威名已存在，就只开放本体两关键词而留下持续授予未实现。父任务可在当前 JC095／JC046 队列完成后再决定是否实施，本文不承诺准入、测试通过或发布。
