# JC032 / JZ24 有限续体待审方案

本文件保留 2026-10-05 的有限方案及依据。两牌和 MSJC03 已进入本地 source33 待审候选；当前实现与真实执行证据见 [Air 候选说明](BLUE_MINIMUM_AIR_CANDIDATE_2026-10-06.md)。地区失效、零项确认和冻结敌席采用已认可的项目规则，不能称为官方 FAQ；原已审 713 和在线版本保持独立。

## 共同的最小来源标记

在现有 `SourceSnapshot` 加一个 `source_region_instance: Option<String>`，带 serde default / skip None，仅两牌捕获。现有 `source.region` 继续存地区索引；新字段存**声明时原地区实例**，避免替换后的同索引地区成为新目的地。不再复制来源、actor、地区或已付费用。已有 actor / source card snapshot / frame cursor / paid costs / command receipts / PRNG 继续使用。

来源牌付费或触发后离场、换 controller、移动或变新实例不消灭已声明效果；actor和原地区标记不跟随这些变化。霸权说明书印刷P10直接说明行动能力发动后与来源分离，并说明触发能力结算流程与行动能力相同；后者的来源独立沿用既有规则机。若原地区实例在首次执行前已被替换，该局部效果失效，保留已付费用/次数、不操作牌库或角色、不消耗随机数，绝不转向新地区。此**地区失效策略是已认可的项目方案**，不是两牌官方 FAQ。正常 pending gate 阻止选择期间其他动作；异常过期选择严格拒绝且状态不变。

## JC032 血族长老

整卡：费用5、蓝忠诚2、死亡领域1；非独有，**仅吸血鬼（无术士）**；永久调查1/战斗1/影响2，防御3。动作2，无横置费用，每回合一次。看自己的牌库顶6张，从中找一个吸血鬼角色，展示并隐匿到这个地区，其他看的牌洗回牌库。有符合牌时必须选1张；没有时选0，不能发明有牌时找不到。

现有 `Op::Search` 是整库至手/顶，不能直接代用。新增唯一封闭操作 `JC032TopSixVampireHidden`，无可配置 N、玩家、过滤器、去向参数；完整 JC032 定义校验阻止移植或扩形。

最小新增载荷：`FrameChoice::JC032TopSix { inspected_ids: Vec<String> }`，有序最多6个现有实例ID。只给操作者的 `Choice` 增加可选 `previewCards`：由这组ID与其原牌库派生全部看过牌，不在状态重复存 Card，不给其他三席输出。现有 options 仅放符合牌，min=max=1、不可跳过。无匹配且非空时建议 min=max=0 的私有查看确认，确认后洗牌；空库直接结束。零匹配查看确认为 UI 项目方案。

首次**效果执行时**（响应之后）固定 `min(6, deck.len())` 的前缀和ID，用印刷 character + Vampire 判定；牌库中的 JC030 印刷为 Bat，不能带入场上条件派生吸血鬼。pending 时前缀留在原牌库，其他动作被 gate；查看、读视图、刷新不改变 ID/PRNG。

选择提交严格核对原地区实例、有序前缀、选择数与符合资格；越界、第7张、错误种类、重复或旧 choice ID 均严格无变化拒绝。成功一次性从库移除所选，公开展示所选牌名，reset zone 得到**新实例**，owner保留，controller设为frame.actor，面朝下进入原地区。展示不把新隐匿实例的身份映射永久公开给其他席；只有当前 controller 得到隐藏牌面。隐匿不触发 Enter/Reveal/Raid。

其余看过牌仍在库中；调用现有 `shuffle_player` 洗**整个剩余牌库**（包括原尾部），不是只洗余下5张。其余牌实例不变，PRNG推进只发生一次提交。存档恢复复用固定前缀、选项、源地区、费用、每回合额度和PRNG，不重新取顶6、不再次付费/洗牌；重复命令走现有回执拒绝。

必要定向回归：库长0/1/5/6/7+，第7张不合范围；无匹配0/有匹配强制1；JC030印刷Bat排除；动作2/每回合一次/不横置；来源离场、移动、借控owner差异与地区替换；六张只在actor视图、所选公开展示后新隐匿ID；不触发袭击；全库尾部洗牌、剩余ID与PRNG；pending/提交后恢复及过期/重复命令无变化。

## JZ24 卡迪纳追迹人

整卡：费用4、蓝忠诚1、**死亡领域1**；非独有吸血鬼/罪犯，永久调查1/战斗2、防御1。Reveal触发，无“强制”，沿用默认可选触发声明；选择发动后符合敌人必须各牺牲其在本地区操控的一个角色（若有）。敌人包含全部对方队伍席位，不选单一敌人；owner不决定选择权。

**用户已认可的项目规则**：2026-10-05主房16:19提案、16:23“认可”——在效果首次开始结算时，一次冻结所有仍在局、手牌≤3的敌方玩家。后续第一人的牺牲/BQ022返还使另一人的手牌变4，另一人仍须牺牲。不得描述为官方牌专属 FAQ；不是在触发声明时取样。

新增唯一固定 `Op::JZ24LocalSacrificeSnapshot`，无通用循环/谓词参数。最小续体 `FrameChoice::JZ24Sacrifice { remaining_players: Vec<usize> }`；当前受影响席使用现有 Pending.seat，其他来源/地区/actor使用同一frame。列表首次结算生成一次，每席完成/无合法角色后弹出头；恢复绝不重测手牌条件。

**具体顺序方案**：复用 `resolution.rs` 现有 `ForEachLivingPlayerFromActor` 的循环席位顺序 `(actor + offset) % player_count`，跳过退出席，再在首次执行过滤敌人和手牌≤3。四席0/1对2/3时，actor0或1依次敌2、敌3；actor2或3依次敌0、敌1。这个顺序是现有机制惯例，供父线程审，不声称官方指定。不能直接复用 make_frame 的展开：它在声明时固定玩家，早于用户认可的取样时点。

每位受影响席的 pending 只列**原地区实例内、正面、由该席当前操控**的角色，min=max=1；隐藏牌不按角色计，沿用 SacrificeChosen；无候选则跳到下一席。效果不针对角色，不添加 Barrier/Shield 目标约束。牺牲调用现有 `remove_dead(Sacrifice)`，宿主离场及 BQ022 回收立即执行，才计算下一席此时实际可牺牲角色；只冻结受影响席，不冻结他们的角色列表。

续体顺序沿用现有选择结算把 frame 放回 effects 队首的行为（`resolution.rs` 的 resolve_frame_choice），使下一席选择先于排在其后的 Death 触发声明。有限 helper 接受已冻结剩余席，立即生成下一 pending 或结束时将 frame 推回队首；不建立通用解释器，不把返回的牌重新用于手牌阈值过滤。保存 pending 即保存完整剩余席和frame，恢复无需新增PRNG或重触发。

**必需两敌交错回归**：A/B开始均手牌3；A先牺牲带BQ022的角色，BQ022 owner=B，立即回到B使手牌4；仍必须显示B的强制牺牲选择并实际完成。覆盖借控角色controller=A/owner=B、A完成到B pending处完整恢复、旧选择及重复提交无变化。对照B首次取样已4则排除，即使稍后降3也不加入。另测可选触发跳过、来源离场、只本地区/原地区实例、没有合法角色、各actor顺序与四席隐私。

历史实际31上的 BQ022 回收证人只证明回收可使B从3到4。当前 source33 的双敌定向测试已实际完成 BQ022 回收后 B 手牌4仍继续牺牲，并在 B pending 处恢复对照；完整正文与四视图见 Air 候选证据包。实现仍待父会话独立审查。
