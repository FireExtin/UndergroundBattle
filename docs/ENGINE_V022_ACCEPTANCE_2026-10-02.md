## Site 兼容及存储失败处理

Site 保留逐字相同的旧 WASM（SHA-256 `a6366ef6bc7df03ba666b33286d3a01c412ac6bf779d6396fcbf6affcdc43966`）。Rust 只导出 schema 与版本字符串；JS 不解析完整私密状态或 u64。旧房间按完整版本元组选择旧核，只有新建房间选择新核；未知元组拒绝，不静默迁移。

实际 workerd/WASM 与本地 D1 SQLite 验证通过：旧核创建的独立本地大厅经普通 API 加入、准备、开始，停在再调度选择；Worker 重开后两席完整视图及原始状态逐字相同。继续选择及重复同一命令返回同一回执、无第二次状态变更。旧房始终标记 `rust-v0.2.1`；新房标记 `rust-v0.2.2`。既有并发 CAS、事务回滚、鉴权、不同意图冲突及最大 u64 验证同时通过。真实生产 D1 发布兼容仍待核实，不把本地模拟器计为远端验收。

存储重试最多两次，有退避和抖动，仅识别 Cloudflare 文档列出的临时错误。每次重复相同座位、commandId、期望版本和行动，鉴权后先读原回执，再执行版本 CAS。提交后响应丢失以原回执确认；提交前失败以同一身份重新尝试；无回执、事务成功或确认结果就继续失败。额度、约束、大小、资源上限、未知错误及 HTTP 拒绝不自动重试。日志仅保留固定原因标签，不记录异常原文、SQL、参数或私密状态。四项有意义的故障测试通过：提交前失败、提交未知但已有回执、不同意图冲突、有限失败预算及无成功伪造。设计依据为 [D1 错误诊断](https://developers.cloudflare.com/d1/observability/debug-d1/) 与 [幂等重试指导](https://developers.cloudflare.com/d1/best-practices/retry-queries/)。
